# 中文局域网工作台

本版本将 Personal OS 的主要工作入口统一为中文的「知行工作台」。保留 Next.js / PostgreSQL 的任务状态与 Python / Markdown 的知识边界，不搬迁真实知识库，不改写历史任务。

## 页面与工作路径

| 入口 | 功能 |
| --- | --- |
| `/` | 工作总览、待处理事项、当前工作焦点、活动摘要 |
| `/tasks` | 看板与列表、搜索筛选、分页、保存视图、站内联动详情 |
| `/wiki` | 空间／手册／章节目录、全文检索、站内阅读和编辑、历史版本、关联任务 |
| `/projects` | 项目目标、当前重点、按任务数量计算的完成情况 |
| `/agents` | 执行者登记、标签、风险权限、启用停用、近期任务与运行批次 |
| `/reviews` | 区分需求确认与交付验收，检查证据后通过、返工或阻塞 |
| `/settings` | 数据库与知识连接、凭证配置状态、执行器接入说明 |

用户填写的资料、执行器名称、代码片段与接口字段保持原样，不自动翻译用户数据。错误提示、操作按钮、状态标签和导航使用中文。

### 任务状态

需求待确认与成果待验收在界面上分开，但仍兼容既有数据库 `review` 状态。通过 `submittedAt` 区分两者。

工作流程：待确认 → 可执行 → 执行中 → 待验收 → 已完成。等待和阻塞是需要解释原因的旁路状态。看板拖动不允许绕过复核直接完成任务；键盘用户可在详情表单中调整允许的阶段。

看板与列表均按 30 条分页。列内计数明确统计当前页，不冒充整个任务库数量。任务详情才加载最近 30 条各类执行历史。保存视图存放在当前浏览器本地存储，也可以直接收藏带筛选条件的地址。

「租约有效」只表示任务仍有有效执行责任，不表示执行器一直在线；心跳也不等于有效进展。页面每 15 秒刷新主要状态，后台执行器不依赖网页是否打开。

### 知识版本

知识按 `space`、`book`、`chapter` 分类，路径不因目录标签变化而移动。新页面生成稳定 ID。

修改必须提交 `expectedRevision`。服务端在文件锁内检查 SHA-256，再原子替换文件。冲突返回 409，前端保留编辑内容，不覆盖他人的修改。历史快照保存在知识数据目录下的 `.workspace-history`，需要一起备份。

从手册创建任务时记录页面路径和版本链接。第二版智能体上下文读取任务引用的具体版本；版本不存在时明确报告缺失，不静默替换成最新版。

`published`、`verified` 和资料级别是维护人明确标注的属性，不是模型自动推断的事实，也不是访问控制实现。实际机密边界必须由访问凭证、任务范围和执行环境共同保护。

新知识服务入口是 `personal-wiki/api/workspace_server.py`，Docker 镜像已切换。不要同时运行旧入口或让多个未经协调的编辑器直接写受管手册。旧的修改／删除／标签写入口在该部署中拒绝写入，需迁移到带版本检查的接口；读取和原始采集接口继续保留。

## 智能体接入

详细契约见 `AGENT_V2_ZH.md`。普通执行器使用独立凭证，不使用管理凭证。执行者身份由凭证确定，不信任请求自报的 `agentId`。

每个写入都绑定任务、执行者和当前运行批次。旧批次或过期租约拒绝继续提交；同一身份默认最多一个有效领取任务。执行者与复核者使用不同角色，执行者不能审批自己的成果。

能力标签帮助匹配任务，但不能充当文件、浏览器或命令的沙箱。执行器需要独立用户、受限工作目录和必要的网络限制。代码提供的停止指令不保证外部已经发出的操作可以撤回，涉及生产部署、付款或公开发布时仍须额外授权。

## 局域网安装

先备份并验证还原，再迁移。不要将真实配置、令牌、知识目录、截图或数据库备份推到公共仓库。

`docker-compose.lan.yml` 不加载演示数据。数据库和知识服务没有宿主机暴露端口，统一经 Caddy HTTPS 入口访问。

在仓库外的受限配置目录中设置：

```text
POSTGRES_PASSWORD
PERSONAL_OS_API_TOKEN
PERSONAL_OS_READ_TOKEN
WIKI_API_TOKEN
WIKI_READ_TOKEN
PERSONAL_OS_AGENT_CREDENTIALS
OS_DOMAIN
LAN_BIND_ADDRESS
```

每个凭证独立生成。数据库密码建议使用至少 32 字符的随机十六进制字符串，避免直接拼入数据库 URL 时出现保留字符编码问题。不要沿用演示凭证。`PERSONAL_OS_AGENT_CREDENTIALS` 格式见智能体手册。

`LAN_BIND_ADDRESS` 默认是环回地址。管理员应明确填写服务器需要监听的局域网地址，并在防火墙中限制来源网段，而不是直接暴露公网。将 `OS_DOMAIN` 配置到内部 DNS，客户端需信任该 Caddy 实例生成的内部 CA。证书未受信任时先正确配置证书，不能把关闭证书验证作为部署方案。

```bash
docker compose --env-file /path/to/private/operator.env -f docker-compose.lan.yml config
docker compose --env-file /path/to/private/operator.env -f docker-compose.lan.yml up -d --build
```

上面的路径是示例，配置文件不应在 Git 工作目录内。`config` 输出可能包含凭证，只能在管理员终端检查，不能粘贴到公共问题或日志。

现有部署应复用原数据库与知识数据卷，不能直接启动空卷后误认为数据丢失。文件中的命名卷仅是新安装示例；升级前由管理员将卷名绑定到真实的既有卷。

浏览器访问使用 HTTPS，应用到知识服务使用独立 `WIKI_INTERNAL_URL`。知识服务读写凭证只留在服务端。

## 备份与回滚

备份范围包括 PostgreSQL、知识数据卷整体（含历史快照与索引）、附件、网关证书及仓库外的配置。先停止执行器和应用写入，再做一致性备份，随后验证还原。

发生故障时先停止执行器，检查在途任务的租约和外部副作用，再回滚应用版本。回滚前后均不得仅凭任务记录判断生产命令已停止。不要以回滚 UI 为理由覆盖较新的数据库或知识数据。

## 验证

```bash
cd personal-os-app
npm ci
npm run prisma:generate
npm test
npx tsc --noEmit
npm run lint
npm run build
cd ..
python -m unittest discover -s personal-wiki/tests
```

独立集成测试只允许连接本地、名为 `personal_os_ci` 的专用数据库，并要求 `ALLOW_WORKSPACE_INTEGRATION=1`。脚本会创建虚构任务与手册，启动隔离的测试服务，不得用于生产库。

```bash
# 数据库地址和测试凭证由隔离测试环境提供。
cd personal-os-app
npm run prisma:deploy
ALLOW_WORKSPACE_INTEGRATION=1 RUN_UI_SMOKE=1 node scripts/workspace-integration.mjs
```

浏览器测试使用真实生产构建及明确的虚构接口数据，验证页面、详情联动、版本链接、只读提示和窄屏导航。数据库集成验证单独覆盖认领竞争、角色隔离、过期批次、版本冲突、固定知识依据和写入边界。截图验证不等于完整无障碍认证，也不代替真实局域网部署验收。

## 明确的版本边界

本版已提供中文主要工作区、基本知识手册维护、任务认领、版本绑定、独立角色、执行器和复核闭环。

以下不是本版已实现的能力：任意层级子任务与可计算的依赖图、甘特图、多人实时协同编辑、细粒度文档级账号权限、真正的外部工具沙箱、按费用自动调度、全量跨服务入库幂等／补偿事务、自动故障转移，以及直接连接用户生产环境的实机验收。不要把界面上的属性标签或能力说明当成这些能力已经存在。

旧 `/api/intake` 的跨数据库与文件服务原子性仍保持原实现；仅新增的手册创建接口具有请求级重放保护。迁移期间应避免无条件重放混合入库请求。
