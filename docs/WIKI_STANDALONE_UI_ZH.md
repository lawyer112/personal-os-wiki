# 独立 Personal Wiki 全站界面交付

## 范围

这一轮改造的是 `personal-wiki` 独立知识网站，不是 Personal OS 内部的 `/wiki` 页面。

| 入口 | 页面能力 |
| --- | --- |
| `/` | 全中文知识总览、真实索引统计、最近笔记、标签入口与概念线稿 |
| `/notes` | 标题和正文搜索、标签和概念组合筛选、来源与状态筛选、分页、卡片/列表 |
| `/note` | 正文、章节目录、双链、反向链接、关联笔记、来源、技术标识与历史版本 |
| `/graph` | 真实索引节点、关系类型、强度过滤、搜索、节点详情、平移、缩放、键盘选择 |
| `/tags`、`/concepts` | 独立索引页、搜索、分页与笔记筛选跳转 |
| `/edit` | 新建和编辑、元数据、写入凭证、版本冲突提示、原文保留 |
| `/manual` | 与当前接口一致的中文 HTML 使用手册 |
| `/auth/read` | 独立知识库读取凭证登录、中文失败提示、原页面返回 |
| 错误页面 | 中文 400、404、500 页面，不将服务器文件路径和异常直接展示给用户 |

原始手册 `/docs/USAGE.md` 保持 Markdown 响应。API 返回结构不因界面换肤而改成 HTML。没有新增删除、归档、权限绕过或自动部署操作。

## 实现边界

站点入口为 `personal-wiki/api/site_server.py`，继承现有版本保护 Handler。原来两个命令行入口的 `main()` 同样转入该站点。旧模块作为接口和解析库保留，默认启动方式不会再显示旧 HTML。

真实业务仍由 `server.py`、`workspace_server.py` 实现。页面只引用知识目录，不重建另一份笔记数据库。Markdown 原文不变；网页阅读器为常用子集，不声明完整 CommonMark 支持。

写入请求只使用用户在编辑页明确提供的知识写入凭证，不把读取 cookie 当作写权限。密钥不落入本地存储或 URL，提交后清空输入。保存超时明确提示结果未知。并发冲突不刷新或清空用户正文。

历史正文来自原有内容哈希快照，关联关系来自当前图谱。图谱一次最多绘制 180 个节点，显示实际截取口径；不把装饰线稿伪装成运行指标。标签/可信度是内容属性，不代表文档级 ACL。

## 视觉与动效

延续工作台的墨色、玉绿和暖金；另有纸白主题。所有资源本地交付，不加载外部字体、图标、粒子引擎或图片。正文与搜索保留高可读性；移动端改为导航抽屉，图谱详情放到画布下面。

页面有轻量入场、卡片悬浮/按压、图形缓慢呼吸与轨道运动。支持手动暂停、系统减少动效、页面后台和装饰图形离屏暂停。图谱布局在数据变化时计算，不持续运行力模拟。

## 局域网部署

`docker-compose.lan.yml` 配合 `deploy/Caddyfile.lan` 为工作台和独立 Wiki 分别提供域名。分别配置 `OS_DOMAIN`、`WIKI_DOMAIN` 与客户端 DNS，信任内部 HTTPS 证书；不得把两个域名设置为同一个值。

Wiki 的 `WIKI_OS_URL` 是可选的工作台导航地址。未配置时页面明确显示独立知识服务，不猜测服务器地址。反向跳转不携带任何凭证；跨域登录仍需各自验证。

本次不直接连接、迁移或重启实际局域网服务。升级时复用现有知识卷和数据库卷，先备份并在隔离副本验证，不运行演示 seed 覆盖正式内容。

## 回归检查

- `python -m unittest discover -s personal-wiki/tests`
- `python personal-wiki/tests/ui/smoke.py`
- `node --check personal-wiki/api/static/wiki.js`
- GitHub Actions `Independent Wiki UI` 运行以上检查与镜像构建。

浏览器测试启动真实 Python HTTP 服务，读写临时知识库，不替换接口为假响应。虚构资料仅用于隔离测试与截图。报告中的通过项以该次工作流运行结果为准。

本轮新增网页鉴权、转义、重定向、只读写入限制与版本冲突测试，但不将这些结果描述为全面渗透测试或绝对安全。
